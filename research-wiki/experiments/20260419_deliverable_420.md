# One-line summary

4.20 mentor deliverable: Qwen3-Embedding-0.6B on `v2_chunks` as a candidate pool hurts R@1 (-7.2pp vs `v1_enriched`), but the same chunks used as **graph rerank context** push 0.6B R@1 to **0.2505**, exceeding the 4B baseline (0.2421).

## Scope

Three items from the 4.20 plan:
1. Re-run 0.6B dense on paragraph-chunked corpus `v2_chunks` (4673 passages).
2. Re-run 0.6B graph rerank using the new chunk v2 graph.
3. Run 0.6B retrieval on the C-Pool 78 universal queries (no qrels).

SLURM jobs: 61418 / 61419 / 61420 / 61421.

## Results — Qwen3-Embedding-0.6B on 473 queries

| Config | R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|
| 0.6B dense `v1_enriched` (reference) | 0.2389 | 0.5127 | 0.5994 | 0.6081 |
| 0.6B + explicit rerank (old chunk v1) static_prior | 0.2357 | 0.5507 | 0.6258 | 0.6166 |
| 0.6B dense `v2_chunks` | 0.1670 | 0.3858 | 0.4968 | 0.4773 |
| **0.6B + rerank (new chunk v2 graph) static_prior** | **0.2505** | 0.4852 | 0.5391 | 0.6162 |
| 4B + rerank static_prior (reference) | 0.2421 | 0.5856 | 0.6448 | 0.6399 |

## Findings

1. `v2_chunks` as a **candidate pool** significantly dilutes signal: corpus grows 2809 → 4673, and R@1 falls from 0.2389 to 0.1670.
2. `v2_chunks` as a **rerank context graph** is the best 0.6B R@1 in the project so far (0.2505), slightly beating the 4B baseline (0.2421).
3. This inverts the assumption in mentor's 4.16 plan that `v2_chunks` should replace `v1_enriched` as the retrieval corpus — it is valuable as graph metadata, not as the document set.
