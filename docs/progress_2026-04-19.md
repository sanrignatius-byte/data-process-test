## 三、多源边叠加机制系统验证

### 3.1 现状（已存在 → 验证）

`scripts/eval_graph_topk_rerank.py` 通过 `--graph-sources {explicit, virtual, cross_doc, summary}` 已支持多源叠加；`merge_adjacencies()` 默认对每条边取 max(weight)。

### 3.2 实验 A：原始叠加（4B 历史结论 + 0.6B 验证）

`data/05_eval/dense_retrieval/stacking_06b/`，static_prior 方法：

| Config | R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|
| **explicit_only**（baseline） | **0.2357** | **0.5507** | 0.6258 | **0.6166** |
| explicit + chunk_seq | 0.2104 | 0.5328 | 0.6237 | 0.5779 |
| explicit + same_chunk | 0.2178 | 0.5243 | 0.6237 | 0.5871 |
| explicit + virtual_all | 0.1987 | 0.5254 | 0.6247 | 0.5633 |
| explicit + crossdoc | 0.2357 | 0.5507 | 0.6258 | 0.6166 (与 explicit 全等) |
| virtual_same_chunk only | 0.1438 | 0.4937 | 0.5994 | 0.4871 |
| crossdoc only | 0.2389 | 0.5127 | 0.5994 | 0.6081 (与 baseline 全等) |

> **发现**：cross_doc 与 explicit 叠加得到与 explicit_only 完全一致的指标 → **cross_doc 在当前实现下完全无连通（pid pair count = 0）**，这是个 bug 不是结论。

### 3.3 实验 B：新增 per-source 权重 + weighted prior（脚本改造）

新增 CLI：
- `--explicit-weight / --virtual-weight / --crossdoc-weight / --typed-crossdoc-weight`（每源边权缩放）
- `--merge-combine {max, sum}`（叠加时同边的合并方式）
- `--prior-mode {degree, weighted}`（degree = 老的 log1p(deg)，weighted = log1p(sum-of-weights)）

`data/05_eval/dense_retrieval/stacking_06b_weighted/`，static_prior 方法关键结果：

| Config | R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|
| [ref] explicit_only | 0.2357 | 0.5507 | 0.6258 | 0.6166 |
| ex1.0 + vir1.0 (degree prior) | 0.1987 | 0.5254 | 0.6247 | 0.5633 |
| ex1.0 + vir1.0 (**weighted** prior, 自动按权重折算) | — | — | — | — |
| ex1.0 + vir0.1 (weighted) | 0.2230 | 0.5412 | 0.6237 | 0.6016 |
| ex1.0 + vir0.2 (weighted) | 0.2146 | 0.5402 | 0.6258 | 0.5892 |
| **ex5.0 + vir1.0 (weighted)** | 0.2188 | 0.5455 | **0.6300** | 0.5980 |
| ex2.0 + vir0.2 + cd0.5 (sum, weighted) | 0.2252 | 0.5423 | 0.6268 | 0.6050 |

> **发现**：
> 1. 老的 `static_prior` (degree-based) 对边权完全免疫；新加的 `weighted` prior 才能让 per-source weight 起作用。
> 2. virtual edges 即使 weight 降到 0.1，也只是逼近 explicit_only baseline，**没有正向贡献**。
> 3. neighbor_prop 对边权敏感且脆弱：vir=1.0 时 R@1 跌到 0.1195。

### 4.4 核心结论

1. ✅ **R@10 历史新高 0.6406**（比 explicit_only +1.5pp），由 typed_crossdoc 或修复后的 section_crossdoc 在 static_plus_neighbor 方法上达成。
2. ✅ **typed edges 单独用就有信号**：figure 单类 R@1=0.2178、table 单类 R@1=0.2125，远好于 section_crossdoc only (0.1575)。
3. ⚠️ **叠加权重很关键**：typed_crossdoc_weight = 0.2 是最佳，>0.5 会稀释 explicit 强信号。
4. ⚠️ **citation boost 几乎没差别**（cited edges 1616/16520 = 10%，0.05 boost 太弱）。后续应扩大 bbl 覆盖（目前 citation_graph 只有 59 docs / 123 边）或调高 boost。
5. ❌ **三源叠加 (explicit + sec_crossdoc + typed_crossdoc) 反而崩**（R@1 0.2008），说明两个 cross-doc 层有信息重叠。
