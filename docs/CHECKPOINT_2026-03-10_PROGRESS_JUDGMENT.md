# Checkpoint（2026-03-10）

## 1. 任务定义（统一口径）
- 项目目标：构建 M4（multi-hop / multi-modal / multi-document / multi-turn）Query 生成与筛选体系，用于训练多模态文档检索 embedding。
- 当前核心方法：从“生成数量优先”转向“监督纯度 + 可证伪评估闭环优先”。

## 2. 当前进度总览（阶段性结论）

### 2.1 已完成并沉淀的能力
1. **方向层共识已经稳定**
   - 不再以“生成多少条”为主 KPI，而是关注：
     - 监督纯度（门禁通过率、泄漏率）
     - 检索增益（Recall@10 / MRR 及其趋势）
     - 失败模式收敛速度
2. **L1/L2 数据工程基础已建立**
   - L1 triage（A/B/C）
   - L2 candidate 构建与 query 生成
   - 多轮复盘确认关键污染源（anchor leakage、泛桥接）
3. **近期 MoDora 整合设计完成（3/10 版本）**
   - A: 节点粒度细化（section 级）
   - B: real-user query 风格与模板体系
   - C: enrichment 质量闸门
   - D: QC 双轨（academic / real_user）

### 2.2 当前真实状态（不是愿景）
- 处于“**方案已清晰，工程待实施验收**”阶段。
- 风险不是方向错误，而是：
  1. 设计点已列出，但关键改动尚未完全进入主干并完成回归；
  2. 质量闸门、生成策略、评估口径三者尚未形成稳定联动；
  3. 若过早扩产，历史问题（泄漏/伪桥接）会再次回流。

## 3. 关键矛盾（优先级排序）
1. **主矛盾：Anchor leakage 与桥接实体语义退化**
   - 直接导致“伪多跳/词面匹配化”，污染训练信号。
2. **次矛盾：评估闭环执行强度不足**
   - 讨论中已确认评估指标，但要进一步产品化为固定报表与准入门槛。
3. **第三矛盾：方案推进顺序可能失焦**
   - 若先做模板扩展再做闸门止血，容易提升表面多样性但降低数据纯度。

## 4. 我的判断（给下一位助手的反思起点）
1. **路线判断：当前路线正确，不建议推翻重来。**
2. **阶段判断：现在最需要的是“把设计变成可验收流水线”，而不是继续讨论新架构。**
3. **执行判断：未来 1~2 周应以“质量闸门先行 + 小规模评估回归”作为唯一主线。**
4. **风险判断：如果没有训练前硬准入，任何扩产都会把噪声放大。**

## 5. 建议的执行清单（可直接交接）

### P0（本周必须）
1. 将 3/10 的 5 个待改文件拆成 checklist：
   - 每个改动点必须绑定：完成标准、回归命令、预期指标变化。
2. 按顺序落地：
   - 先 C（enrichment 质量闸门）
   - 再 D（QC 双轨 + retrievability）
   - 再 B（real-user 模板与 query-style）
   - 最后 A（section 粒度与路径扩展）
3. 建立双轨固定报表：academic vs real_user 分开统计
   - pass rate
   - leakage rate
   - retrievability_score 分布
   - BM25 / dense 趋势对比

### P1（下周）
1. 建立训练准入白名单（硬门禁）：
   - `qc_pass=true`
   - leakage 低于阈值
   - evidence closure 通过
2. 失败样本（B 类 / qc_fail）沉淀为 hard negative 池，不再混入正样本训练集。
3. 设置扩产闸门：
   - 仅当 clean subset 在核心指标上持续改善，才扩规模。

## 6. 一句话结论
- **项目已从“盲目扩产”切换到“质量驱动”正确轨道；当前成败关键不在新想法，而在把既有方案落实为可回归、可准入、可复盘的工程闭环。**
