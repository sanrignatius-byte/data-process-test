# 专利申报凝练稿（生产线版）

**发明名称（建议）**：一种多模态多证据检索训练数据的自动化生产方法、系统及存储介质

> 本版定位：**只保护已经落地、已交付、且经验证能显著提升我方模型多模态文档处理能力的 m2query 生产流水线本身**。
> - 保护对象 = 当前实际运行的整条生产线（异构证据图 → hub 多跳约束生成 → 多证据必要性 QC → 三元组打包），以及其中三个已交付、公开文献无对位的工程手段：**bridge 桥接证据两段式封装**、**检索单元 chunk 兜底聚合**、**训练负样本模态级重平衡**。

> - 实施例口径：以已交付的 **M4query_v2_clean_chunk_aug**（8,104 条 query / corpus 169,671 passage）为主实施例，所有效果数据围绕它。

## 一句话主张

本发明提供一种**把复杂科研/技术文档自动转化为「必须联合多个跨模态证据才能回答」的检索训练数据**的生产方法：先将文档组织成一张以作者显式引用关系为骨架的**六粒度异构证据图**（figure/table/formula/paragraph/section/chunk），在图上挖掘多跳证据路径，用路径约束大模型生成 grounded 的 query/answer/reasoning chain，经多证据必要性质量控制后，打包成可直接训练检索模型的三元组。

其价值已被验证：用本生产线产出的数据训练检索模型，模型的多模态文档检索能力显著提升。

答辩口径：

> 我们把复杂文档变成一张六粒度的可信证据图，并用这张图约束大模型，**成规模地、可控地**生产出多模态、多证据、可直接训练的检索数据；用这批数据训练后，模型的多模态文档处理能力有可度量的提升。

## 发明背景

现有多模态检索训练数据通常是「一问一图」或「一问一段」，难以覆盖真实文档中「公式定义方法、表格给出结果、图展示趋势、正文解释条件」这类需多证据联合推导的关系。

人工标注此类数据成本高、规模受限；直接让大模型自由出题又易出现三类问题：(1) 关系编造与答案幻觉；(2) 生成「单证据即可回答」的伪多跳样本；(3) query 泄漏视觉 anchor 或关键数值，使检索可被词面匹配「作弊」。

此外，即使能生成多证据问题，要让它**真正可用于训练检索模型**，还需解决三个被现有方法忽视的工程难题：

- **难题一（跨文档桥接证据污染语料）**：多跳推理链常带一个「桥接段落」，直接入库会在检索语料中引入不属于任何文档的游离 passage，破坏语料一致性、干扰负样本采样。
- **难题二（检索单元粒度与多证据信号错配）**：若以滑窗 chunk 作为唯一检索单元，单个 chunk 往往只能覆盖多证据中的一个，稀释「必须联合多证据」的训练信号。
- **难题三（训练负样本的模态分布偏置）**：按语料自然分布采负样本时视觉模态占比过高，训出的检索器对视觉模态过拟合、对文本证据欠敏感。

本发明将「多模态多证据数据的可信生成」与上述三个「可训练化」工程难题作为一个整体解决，形成一条**端到端、可规模化、产出物可直接训练**的生产流水线。

## 拟解决的技术问题

如何自动、低成本、可信地从复杂文档批量生产「必须联合多个跨模态证据才能回答」的检索训练数据，并使该数据可直接用于训练检索模型、带来可度量的多模态文档检索能力提升。

## 核心技术方案（生产流水线，已落地）

```text
文档（科研论文等）
  → ① 多粒度多模态元素解析（figure/table/formula/paragraph/section/chunk）
  → ② 基于作者显式引用关系构建六粒度异构证据图
  → ③ hub 节点与多跳跨模态证据路径挖掘（严格文档内约束）
  → ④ 图路径约束的大模型生成（query/answer/reasoning chain）
  → ⑤ 多证据必要性质量控制（单元素消融 + 答案 grounding + 规则 QC）
  → ⑥ 桥接证据两段式封装（★难题一）
  → ⑦ 检索单元 chunk 兜底聚合（★难题二）
  → ⑧ 三元组打包 + 负样本模态级重平衡（★难题三）
  → 可直接训练的检索三元组（多正例 + 分层 hard negative + random negative）
```

### ① 多粒度多模态元素解析
解析文档得到多粒度元素，每个元素带 `doc_id + element_type + page_idx + position_idx + content/caption/context + image_path + bbox`，覆盖 figure、table、formula、paragraph、section、chunk 六种粒度。

### ② 六粒度异构证据图构建
利用文档作者写下的显式引用关系（"Figure N"/"Table M"/"Eq. K"/`\ref{}`）作为高可信连边，将六种粒度元素组织为一张异构证据图。该图区别于纯文本知识图：节点是跨模态的多粒度证据元素，边来自作者真实标注的引用，而非语义相似度推测。

### ③ hub 与多跳路径挖掘
以「覆盖多种模态、被多段正文引用」的 bridge-first 准则对节点评分，选出 hub 节点，枚举连接不同模态的 2-hop/3-hop 证据路径作为多证据候选；并施加**严格文档内约束**，保证候选证据来自同一文档、零跨文档泄漏。

### ④ 图路径约束的大模型生成
将证据路径、桥接段落原文、元素描述作为约束输入，让大模型在该约束下生成 query、answer 与 reasoning chain；生成约束包括去命名（不在 query 直接写桥接实体名）、禁用弱模板、禁泄漏视觉 anchor 与关键数值、答案须含机制连接词。使生成结果既自然又证据可追溯。

### ⑤ 多证据必要性质量控制
- **单元素消融**：删去任一证据后应不可独立回答，否则判伪多跳；
- **答案 grounding**：每个正例须能被 query 直接锚定，否则判幻觉；
- **规则 QC**：hop 不重复使用单一文档、不跨越式桥接、因果方向 premise→intermediate→conclusion。
仅必要性达标的样本进入交付集（pass-only），通过率约 25–30%。

### ⑥ ★桥接证据两段式封装（难题一）
对每个携带跨文档桥接文本的样本：
- **第一段（源段落替换）**：能在语料中定位到桥文本对应的真实源段落时，将桥接节点替换为「源段落 + 其所在 chunk」，正例数随之提升；
- **第二段（合成节点保留）**：找不到源段落、或源是图/表/公式时，把桥文本本身改类型为 paragraph 作为合成节点入库，并以专用命名规则（如 `<query_id>_bridge`）避免与真实段落 ID 冲突。
使训练样本在保留多证据推理信号的同时，不向检索语料引入游离 passage。实施例中两段分别覆盖 86.9% / 13.1% 的桥接样本。

### ⑦ ★检索单元 chunk 兜底聚合（难题二）
按 section 边界、以约 400 词软上限聚合 paragraph 成 chunk，**不跨 section、不滑窗、不重叠**；并为每条 query **必附一个 chunk 正例兜底**——即使图/表/公式未被召回，section 级 chunk 仍能给检索一个降级信号。该聚合规则区别于主流框架（512 token + overlap）的默认切分。

### ⑧ ★三元组打包 + 负样本模态级重平衡（难题三）
每条通过 QC 的 query 打包为：3–4 个正例（同篇 figure/table/formula/paragraph 原始证据 + section chunk 兜底）、5 个 hard negative（以同文档其它干扰元素为主、少量跨文档话题相邻，防止只学到文档 ID 这种 shortcut）、5 个 random negative；并将 visual:text 负样本比例从语料自然分布的 72:28 **重平衡到约 45:55**，避免检索器对视觉模态过拟合。

## 核心创新点

> 本发明的可保护性来自**整条流水线的具体组合**，以及其中三个已交付、公开文献无对位的工程手段。各创新点均已在生产中落地并产出交付数据。

### 1. 面向作者引用关系的六粒度异构证据图
不让大模型凭空理解全文自由出题，而是把作者真实存在的显式引用转化为机器可用的六粒度（figure/table/formula/paragraph/section/chunk）异构证据图，显著降低关系编造风险，使问题建立在文档原本存在的逻辑连接上。区别于纯文本多跳生成方法（仅文本节点）与文档内图文链接方法（仅图–文两类、依赖干净 caption）。

### 2. 图路径约束的多模态多证据生成
通过 hub、桥接关系与多跳路径自动发现跨模态证据组合（非随机拼接），并以路径约束大模型生成，使生成样本天然适合「必须联合多个跨模态证据才能回答」，且证据可追溯。

### 3. 面向「多证据必要性」的质量控制
QC 不止检查文本通顺，而专门验证：单证据不能独立回答、答案必须由多证据共同推出、query 不泄漏视觉 anchor/关键数值、answer 无无支撑幻觉。这是普通文本生成 QC 不具备的。

### 4. 桥接证据两段式封装（让跨文档推理信号「装进」可训练样本）
见技术方案 ⑥。这是让生产出的样本既保留多证据推理信号、又不污染检索语料的核心工程手段。

### 5. 检索单元 chunk 兜底聚合（不跨 section + 必附兜底）
见技术方案 ⑦。从「chunk 作唯一检索单元会稀释多证据信号」这一失败反推出的设计，非行业默认。

### 6. 训练负样本的模态级三层重平衡
见技术方案 ⑧。公开多模态检索数据集均不做模态级重平衡，本手段直接针对视觉过拟合。

## 建议保护点（权利要求布局）

采用「方法独立权利要求 + 系统/装置独立权利要求 + 存储介质权利要求」三件套；**独立权利要求即整条生产流水线**，三个工程手段（封装/兜底/重平衡）与必要性 QC 作为从属权利要求逐条加固。

### 独立权利要求 1（方法，骨架）

> 一种多模态多证据检索训练数据的生产方法，**其特征在于**包括：
> (a) 对文档解析得到多粒度多模态元素，所述元素至少包括 figure、table、formula、paragraph、section、chunk，每个元素带有文档标识、类型、位置与上下文；
> (b) 基于文档作者的显式引用关系构建文档内异构证据图，所述显式引用关系来源于文档源码中的引用标记或对解析文本中 "Figure N"/"Table M"/"Eq. K" 类引用标记的抽取；
> (c) 在所述异构证据图上，以覆盖多种模态为准则选取 hub 节点，并枚举连接不同模态的多跳证据路径，所述路径受严格文档内约束；
> (d) 以所述证据路径约束大模型生成 query、answer 与 reasoning chain，所述约束包括禁止在 query 泄漏视觉 anchor 与关键数值；
> (e) 对生成结果进行多证据必要性质量控制，所述质量控制包括单元素消融测试与答案 grounding 校验，仅必要性达标者进入交付集；
> (f) **将含桥接证据的样本经两段式封装**——能定位源段落时以源段落及其所在 chunk 替换桥接节点，否则将桥接文本作为合成 paragraph 节点入库；
> (g) 为每条 query 打包多个正例、分层 hard negative 与 random negative，**所述正例包含一个按 section 边界聚合且不跨 section 的 chunk 兜底正例**，**所述负样本经视觉与文本模态比例重平衡**，得到可直接用于训练检索模型的三元组数据。

### 从属权利要求（加固）

1. 步骤 (b) 所述显式引用关系来源于 LaTeX `\ref`/`\cite` 标记，或来源于对 PDF 解析文本的正则抽取。
2. 步骤 (c) hub 评分采用 bridge-first 准则：按节点覆盖的模态数与被引段落数加权。
3. 步骤 (c) 多跳路径长度为 2-hop 或 3-hop，且端点为不同模态元素。
4. 步骤 (e) 质量控制进一步包括 premise→intermediate→conclusion 因果方向校验，及 hop 不重复使用单一文档的规则。
5. 步骤 (f) 合成 paragraph 节点采用专用命名规则（passage_id 后缀 `_bridge`）以避免与真实段落 ID 冲突。
6. 步骤 (g) chunk 聚合采用约 400 词软上限、不滑窗、不重叠；且每条 query 必附且仅附确定数量的 chunk 兜底正例。
7. 步骤 (g) 负样本 visual:text 比例落入约 40:60 ~ 50:50 区间。
8. 步骤 (g) hard negative 以同文档其它元素为主、辅以跨文档话题相邻元素。
9. 步骤 (d) 生成约束进一步包括去命名约束（不在 query 直接写桥接实体名）与机制连接词约束。
10. 步骤 (d) 生成时按确定性规则为不同候选分配读者人设（persona），以增强 query 多样性。
11. 多跳证据链可进一步投影为多轮 session，并以「抹除前一轮回答后当前轮不可答」作为 turn-dependency 质量控制。
12. 系统/装置权利要求：包含解析模块、建图模块、路径挖掘模块、生成模块、QC 模块、封装与打包模块。
13. 计算机可读存储介质权利要求：存储指令，执行时实现上述方法。

> 布局说明：(f) 封装、(g) 兜底+重平衡是三个已交付且新颖的工程手段，直接写入独立权利要求主体；即使 (a)-(e) 的框架部分被现有技术缩限，(f)(g) 仍使整体组合具备新颖性。

## 有益效果（拆两类归因）

### A. 数据生产侧效果（本方法直接效果，可核实）

- **自动化、可规模化产出**：主实施例单版交付 **8,104 条 query**、对应 corpus **169,671 条 passage**（paragraph 117K / chunk 29K / figure 9K / table 7K / formula 6.9K），覆盖六种粒度证据；累计多版产出规模更大。
- **产出质量可控**：经多证据必要性 QC（单元素消融 + grounding + 规则 QC）筛选，pass-only 通过率稳定在约 25–30%，保证仅「真多证据」样本入库。
- **可训练化处理完整**：桥接证据两段式封装（86.9% 源段落替换 / 13.1% 合成节点）、chunk 兜底、负样本模态重平衡（72:28→45:55）使产出物可直接用于训练。

### B. 下游模型能力提升（核心价值，本生产线产出数据的训练效果）

> 本节是本专利最重要的技术效果：**用本生产线产出的数据训练检索模型后，模型的多模态文档检索能力显著提升。** 请在申报时补入「训练前 / 训练后」对照的具体评测数字（如在自有测试集上的 R@K、MRR 提升）作为主证据。

## 与现有技术的区别（背景技术对照）

| 现有技术 | 其做法 | 本发明的区别 |
|---|---|---|
| 纯文本多跳问答生成（如 HopWeaver 类） | 仅文本节点、文本多跳；规则 QC | 本发明是**多模态、六粒度异构图**，证据含图/表/公式，且产出物是**可训练检索三元组**（含桥接封装、chunk 兜底、模态重平衡），非仅问答对 |
| 文档内图文链接（Connecting-the-Dots 类） | 仅图–文两类、依赖干净 caption、限文档内 | 本发明覆盖六种粒度、利用作者显式引用而非 caption 相似度，并完成到训练数据的全链路打包 |
| 公开多跳数据集（HotpotQA 等） | 跨文档桥以独立 passage 存在；不区分模态 | 本发明以**两段式 fallback** 将桥接信号封装进样本、不引入游离语料，并做**模态级负样本重平衡** |
| 主流检索切分（512 token + overlap） | 滑窗、重叠、不感知 section | 本发明 chunk **不跨 section、不重叠、必附兜底正例**，针对多证据信号稀释问题 |
