# MinerU-only Migration Plan — after LaTeX-centric attempts

**Date**: 2026-05-19  
**Scope**: `data-process-test` experimental lane first  
**Status**: design + readiness audit complete; implementation should start as experimental `experiments/` scripts, not production `src/`

---

## 0. Why pivot

The LaTeX-centric route gave useful diagnostics but is no longer the right foundation:

1. **Coverage mismatch**: current working set has far more PDFs/MinerU folders than usable LaTeX sources. LaTeX is opportunistic, not guaranteed.
2. **Mapping loss**: prior MinerU→LaTeX alignment audits showed high loss for figure/table matching; relying on LaTeX labels makes the pipeline brittle.
3. **Wrong primary unit**: mentor guidance is PDF-first: enrich the available PDF/MinerU evidence rather than building around LaTeX references.
4. **Empirical ceiling**: line-number/topology fixes did not move the main retrieval ceiling; formula issues were mostly representation-bound, not topology-bound.

Decision: keep LaTeX-derived artifacts as **legacy baselines and diagnostic controls**, but migrate new graph/query generation to **pure MinerU artifacts**.

## 2. Replace LaTeX primitives with MinerU primitives

| Old LaTeX-centric primitive | Problem | MinerU-only replacement |
|---|---|---|
| `latex_reference_graph*.json` paths | requires LaTeX source; label mapping loss | `mineru_local_graph`: reading-order + reference regex + co-mention + layout-near edges |
| `line_no` / `.tex` line ranges | unavailable for PDF-only docs | `(page_idx, position_idx, bbox, image_path, local context window)` |
| LaTeX label → MinerU element mapping | figure/table loss; formula mismatch | direct MinerU `element_id` as canonical ID |
| section enrichment from LaTeX metadata | dependent on source text | section/text nodes from MinerU headings + neighboring paragraphs |
| LaTeX citation / BBL crossdoc | useful but scarce | optional later: parse PDF reference section + semantic crossdoc matches |
| Method-C long chains | deprecated; too brittle | short 2–3 node MinerU chains with explicit evidence spans |

## 3. Target MinerU-only schema

Create an experimental normalized artifact first, e.g.:

`data/05_eval/mineru_only_graph_v0_*/mineru_elements_v0.json`

Each node should have:

```json
{
  "element_id": "docid_type_position",
  "doc_id": "...",
  "element_type": "text|section|figure|table|formula",
  "content": "raw extracted text / formula / table text / caption",
  "caption": "caption if available",
  "page_idx": 0,
  "position_idx": 12,
  "bbox": null,
  "image_path": "...",
  "context_before": "...",
  "context_after": "...",
  "source": "mineru.structure|mineru.content_list|mineru.markdown",
  "quality": {
    "has_content": true,
    "has_caption": false,
    "has_context": true,
    "has_image": false,
    "richness": 1234
  }
}
```

Important design choice: **text paragraphs are elements**, not merely context strings. This aligns with mentor’s terminology: paragraph/text is an element peer to figure/table/formula.

## 4. MinerU-only edge families

Build edges without LaTeX source:

1. **Reading order edges**
   - `next_element`: adjacent elements by `(page_idx, position_idx)`.
   - `same_page_window`: elements within ±K positions on same page.

2. **Context containment edges**
   - `context_before_contains`: text/section → figure/table/formula when it is immediate local context.
   - `caption_of`: caption/text block → visual/table/formula element if caption extraction separates them.

3. **PDF reference regex edges**
   - from text paragraphs mentioning `Figure N`, `Table N`, `Eq. N`, `Section N` to numbered MinerU elements.
   - This reuses the robust part of `MultimodalRelationshipBuilder`, but the source text is MinerU text elements, not LaTeX.

4. **Layout-near cross-modal edges**
   - figure/table/formula ↔ nearest text/table/figure/formula on same page.
   - Score by page distance, position distance, caption/context richness.

5. **Semantic local edges**
   - embed captions + context + text paragraphs; add top-k same-doc edges with strict threshold.
   - This is optional after structural edges are audited.

6. **Cross-doc semantic edges**
   - reuse the current archive cross-doc matches as seed only for pilot.
   - rebuild later from MinerU-only rich text/image descriptions across docs.

### Phase 1 — MinerU-only normalized graph v0

Add experimental script:

`experiments/build_mineru_only_graph_v0.py`

Inputs:

- `data/00_raw/mineru_output/*/structure.json`
- `data/00_raw/mineru_output/*/formulas.jsonl`
- optional `content_list.json` / markdown if present

Outputs:

- `mineru_elements_v0.json`
- `mineru_edges_v0.jsonl`
- `report.md`

Gate:

- ≥95% of `structure.json` docs parsed without exception.
- text elements present in ≥70% of parsed docs, or report why raw MinerU lacks body text.
- image path resolution ≥90% for figure/table image-like nodes.

Current blocker: only 80/1153 doc dirs expose `structure.json`; full-scale migration needs regenerating or locating missing MinerU structured outputs.

### Phase 2 — candidate generation without LaTeX

Add experimental candidate builders:

- same-doc cross-modal: text ↔ figure/table/formula, table ↔ figure, formula ↔ table.
- cross-doc + cross-modal: same-modality semantic bridge + local cross-modal MinerU neighbor, continuing the current 3-node design.
- session projection: turn chain nodes into 2-turn or 3-turn user sessions only after single-query chains pass quality.

Candidate score:

```text
score = local_edge_confidence
      + richness_bonus
      + modality_balance_bonus
      + source_doc_diversity_bonus
      - long_distance_penalty
      - missing_context_penalty
```

Gate:

- 24 candidates, source-diverse, at least 6 per base type.
- manual QC: removing any one node makes the answer incomplete in ≥70% of reviewed candidates.

### Phase 3 — query generation API smoke

Use company API only through:

- `src.api.call_llm(provider="company")`
- fixed logger: `api_logs_cannt_delete`
- token total: `logs/token_usage.db`

Gate:

- 9-call smoke first.
- `parsed_ok ≥ 8/9`.
- every parsed query has exactly 3 evidence spans and explicit chain roles.
- no production `src/` changes.

### Phase 4 — retrieval evaluation

Build retrieval corpora from MinerU-only elements:

1. raw element text only;
2. additive PDF-context text (`content + caption + local text`);
3. optional LLM-enriched descriptions for selected nodes only.

Evaluate:

- dense baseline;
- graph rerank with only MinerU edges;
- ablation: remove layout edges / remove regex reference edges / remove semantic edges.

Gate:

- Must beat or match current experimental chain generation quality before any production merge.
- Retrieval does not need to beat old LaTeX graph immediately, but must show cleaner coverage and lower mapping loss.

---

## 6. What not to do

- Do not “fix” the old production cross-doc filter; it is an intentional guardrail.
- Do not promote `structure.json` parsing into `src/` until Phase 1/2 artifacts pass gates.
- Do not replace corpus text with visual enrichment; F2 showed replacement/additive corpus-level visual enrichment can regress retrieval.
- Do not rely on LaTeX line numbers, labels, BBL citations, or long LaTeX paths for any new MinerU-only claim.
